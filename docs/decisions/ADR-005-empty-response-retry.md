# ADR-005：空正文/仅推理响应的重试

- 状态：已接受（2026-10-24）
- 决策者：项目所有者

## 背景

P2 基线里出现过 `FinishReason=stop`、正文为空、只有 reasoning（或只有少量 token）的响应。传输层没有失败，`TurnPipeline` 也会正常 `Completed`，但用户看到空回复。对读路径工具场景，这种空响应不应该直接当成成功。

重试必须满足安全条件：没有工具调用 = 没有副作用；有工具调用时重试可能重复写/重复读，不能自动做。

## 决策

1. **模型级重试。** 新增 `EmptyResponseRetryChatModel` 包装 `IChatModel`；只对“本次模型调用没有正文、没有 tool call、`finish_reason` 为 `stop` 或 null”的响应重试。
2. **不重试的情况。** `length`（截断）、`tool_calls`、异常/取消都不重试；`length` 需要宿主调大 `max_tokens`，不是重复调用。
3. **默认 1 次。** `MafAgentEngineOptions.MaxEmptyResponseRetries` 默认 1；0 表示关闭；可经 `IConfiguration` 绑定。
4. **不改变事件契约。** 重试发生在 `IChatModel` 边界内；`MafAgentEngine`/`TurnPipeline` 仍只看到一次逻辑模型流。第一次尝试已经产生的 reasoning/usage 仍会进入流与 token 统计。
5. **只用于模型响应，不用于工具。** 工具拒绝/失败仍通过 `ToolResult.Ok=false` 回喂；不在工具层重试。

## 后果

- 正面：空正文的 `stop` 响应多一次机会；无工具调用，安全；配置可关闭；有单测覆盖“重试一次”和“关闭后保持空”。
- 负面：重试会增加一次模型调用延迟与 token；第一次尝试的 reasoning 可能已经展示；如果模型连续空响应，最终仍会返回空正文，宿主仍需健康检查/提示。
- 边界：这不是“保证非空”的机制；只是降低空回复概率。真正的用户可见兜底（例如“模型未返回内容，请重试”）在宿主/端点。

## 考虑过的替代

| 方案 | 未选原因 |
|---|---|
| 在 `TurnPipeline` 重试整个回合 | 已经 yield 过的事件无法撤回，reasoning/usage 会重复；也可能重复工具副作用 |
| 宿主编排重试 | 每个宿主重复实现，安全条件容易漏 |
| 不重试，直接显示空 | 用户可见空回复；P2 基线已观察到 |
| 对所有空响应重试 | 包含 `length`/有 tool call 的情况，可能放大成本或重复副作用 |

## 复审条件

- 模型在带 tool call 的响应里也频繁出现空正文；
- 宿主需要跨回合、带预算的重试编排；
- 供应商提供“空响应”专用错误码，可以在更低层处理。
